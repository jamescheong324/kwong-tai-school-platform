時間：2026/9/2
地點：勞校中學
對接人：孫戈明
議題：借鑒勞校系統打造經驗

1. 系統後來要加功能，加得動嗎？哪些規則每年都變？
答：系統主要developer是釗哥（常在校長室coding），功能相對好加，一天能改三個版本代碼；規則常改，會談期間有老師前來向孫戈明提需求改餘暇活動班計分規則，孫戈明建議不要hard code param 和 config。

2. 老師最常抱怨甚麼？聽某些老師說系統太冗余。
答：或者是因為一般老師權限不夠，未必感受到系統好用處。孫戈明表示在他們開發者角度，勞校系統最大問題是DB太舊、屎山代碼多，因勞校在20年前開始用本地server存data及開發個別系統，近年主要做intergration；如果我們能將整套系統做出來並package成產品（乾淨db及代碼），勞校也會採購。
釗哥想package出去，但...

3.一開始哪步最難？
答：勞校本來已有近20年data在本地server的data warehouse中，亦有多個系統。起初最難的是intergrate各系統時SSO問題，用windows AD服務有不少成本，勞校SSO（學生）是用：姓名＋教青局學生編號＋生日。

4.maintain難點在哪？硬件如何maintain？系統是否有備份、在哪、有否演練。
答：一方面user使用系統方法千奇百怪，db被整壞不只一次；另一方面硬件設備也是難點。會談期間勞校render A壞了，轉用render B，然後叫了光大數碼科技公司（硬件及服務供應商）維修員來學校去機房維修。所以是學校+第三方供應商共同維護。備份有本地git，冇做演練（因不像銀行有硬性要求）。

5.資安如何做？有被攻擊嗎？
答：勞校有位老師（前pwc資安員工）負責，之前有用eVault和CTM資安服務（SOC等），現在都不用了，可以說是沒有。沒有發現被攻擊事件。

6.放雲？
答：澳門《個資法》對資料傳輸外地有要求，需要全部家長簽同意書（可查澳門個資法相關要求）。或放ctm雲，但貴。孫戈明說澳門絕大部份學校用on-prem，有些用eClass(香港公司)，他有了解個eclass早年有技術員在澳門，幫學校本地部署，但現在不清楚，可能偷偷用外地雲也說不定。

7.教青局系統不兼容
答：是，且學校也不想兼容，教青局系統的格式更差，也不好讀。

孫戈明的其他建議：
1.先定好底層架構，建議用Postgre+python，缺點是python framework 不多。但用php的話有安全問題？

2.將系統連入wecom, wechat有market，勞校已連wechat, 未連wecom。

3.市場方向轉為一整套解決方案。如匯盈科技有限公司做機器人教室項目時會連同教室設計、裝修、教桌椅、教具、機器人一併交付給學校。建議我們可以利用表哥家具行業資源拓展除軟件之外的其他項目，打包並重新包裝賣給學校。

4.釗哥有心想package勞校系統出去賣，但孫戈明認為目前系統太過customized，難以直接複製。建議我們可以讓邦哥和釗哥談談，那麼我們就可以和孫戈明他們對接改進，兩方合作將系統打包成產品。
