日期：2026-09-26

> **這些數字只是訂成本上限的線索，不是報價，也不是法律或稅務意見。**

## 2. 可辯護的成本上限算法

人日數和工作日換算由團隊填寫。這裡不代填，也不給出項目總價。

對每一個角色 r：

`人工成本_r = （月工作收入基準_r ÷ 每月工作日_r） × 人日_r`

`直接人工合計 = 各角色人工成本之和`

`社保現金 = 澳門元 60 × 該名本地長工僱員的受僱月數`（每名符合強制性制度的長工僱員；見上表，這是月定額，不要再乘一個百分比）

`成本上限 = 直接人工合計 + 社保現金 + 已同意入帳的第三方發票面額`

約束：

- 月工作收入基準只用第1節（a）已引用的數字，並寫明是就業調查的中位數，還是薪酬調查的全職僱員平均薪酬，以及用的是哪一個職業或行業。這些都不是程式員薪酬。
- `每月工作日` 和 `人日` 都是團隊輸入。就業調查只公布每週實際工作時數中位數（專業人員 41.9 小時），沒有公布每月工作日，不能從表內直接得到日薪。
- 不加利潤、不加風險金、不把第1節（b）的判給價除以人日來倒推日薪。
- 若公司沒有設立公積金共同計劃，不要把第7/2017號法律第二十六條的百分之五算進強制成本。該比率只在共同計劃之下適用，制度本身是非強制的。

### 演算例子（不是上限）

只用已引用的數字，其餘標成假設。

- 月工作收入基準：就業人口「專業人員」中位數澳門元 40,000（2025年第3季至2026年第2季）。這不是程式員薪酬。
- 假設每月工作日 D = 22。這個 22 不是統計暨普查局數字。
- 假設人日 N = 1，只為展示算式。

則該 1 個人日對應的收入部分 = 40,000 ÷ 22 = 澳門元 1,818.18。

項目總價仍不能算出來，因為真正的人日、角色組合、每月工作日、第三方發票都還沒有填。社保是每月 60 元，不是按這個 1 人日再乘一次。

## 3. 不應拿來比的東西

- 按學生人數計費的 SaaS 月費或年費。那是使用費，不是這次自建系統的直接人工加發票。
- 內地外包人月報價。今次判給裡出現的廣州公司澳門分公司，標的是公務通這一類大型政府系統，金額是判給價，不能當成澳門本地成本日薪。
- 企業 ERP、雲平台、核心系統授權和維護（上表 T24、專有雲、雲設備）。範圍和計價方式都不同。
- 教青局或教育基金的資助額。本項目不使用該等資助，資助上限也不是開發成本。
- 把「專業人員」中位數當成程式員工資。官方分類沒有拆到這個職系。

## 4. 缺口

- 沒有找到官方的澳門程式員、系統分析員或資訊科技職系薪酬，因此沒有官方成本日薪。
- 沒有找到與本期學校行政系統規模相近的定製開發判給。已見的開發判給是數千萬至一億元以上的政府系統。
- 公共採購平台（https://www.pcp.gov.mo/）頁面設定寫明開放日期 2026/09/01（https://www.pcp.gov.mo/gpcms-center-web/static/config.js），但公告接口返回 token 校驗失敗，今次沒有查出 2023–2026 年的小型系統判給。
- 香港數字政策辦公室今次沒有取到常設聘用協議或資訊科技專業服務的人日價目表，所以沒有使用港元日薪。
- 沒有找到一條「僱主必須按工資某個百分比計入成本」的強制附加費率。強制的現金供款是上面的每月 60 元。百分之五只存在於非強制的公積金共同計劃。
