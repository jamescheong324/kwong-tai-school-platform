## 一、會議重點（TL;DR）

1. **重大修正：廣大並非「無系統」**。校方已有多套並存、互不相通的系統——上海公司**師悅**開發的**學籍管理系統**（今年啟用）、**e-Class**（打卡／家長通知／資產）、**科大訊飛智學網**（出卷／評估），加大量 Excel 與紙本。上次紀要「以為廣大冇系統」的假設需更新。
2. **關鍵洞察：師評＋審批是市場空白**。無論科大訊飛、e-Class 或師悅學籍系統，**都沒有「教師評鑑（師評）」與「行政審批」**這兩塊——這是我方最不撞車、最容易切入的缺口。
3. **切入策略＝游擊隊，唔好一次過換晒**。馬sir 强烈建議：不要試圖一口取代所有系統（「唔好諗住一口食晒隻大象」），而是集中火力做一個「最痛、最細、最快見效」的功能，做出示範與口碑，再逐步擴張。
4. **團隊首期建議：M2 教師（師評）＋ M5 行政審批（＋ M6 資產）**，以**企業微信（WeCom）小程序、本地部署**形式落地，貼合老師既有使用習慣。
5. **合規是硬約束**：澳門《個人資料保護法》（第8/2005號法律）要求學生／教師資料不出境；學籍數據存於 CTM 本地伺服器，e-Class 數據則在香港（家長會已簽署同意書）；教師個資需 hash／加密後方可上雲。
6. **商業／政策面**：善用澳門「扶持青年創業、產業多元化」政策，爭取教青局資助（AI 專項等）與政府／中聯辦／北大等背書，以廣大作示範，再推向全澳 **68 間私校**（尤其中小型）。

### 2.2 學籍管理系統（供應商：師悅）——分三期

- **第一期（已完成）：** 基礎學習成績管理 ＋ 部分行政；用戶＝校內老師／校長／主任；**未對學生、家長開放**；老師下星期開始培訓。
- **第二期（擱置中）：** 原擬取代 e-Class 的家長端功能——學校通知（部分需簽名）、學生「一本記錄」、成績（電子發放）、操行表現、比賽／出隊。因**校方今年計劃調整、朱sir 有新想法（可能另有供應商或想自研）、教青局方向未明** → 暫停。
- **第三期（規劃中）：** 學生自助——學校活動報名、課後班報名、「新成長個案」（學生自填興趣／校外活動），學校補充；目標產出**完整學生檔案（高一至畢業）**。
- **本地化：** 目前用「通用版」，**澳門校本化預計 10 月完成**；學生資料（家長、住址等）**目前仍在 Excel、未上傳**，待校本化完成後再 upload。
- **教師數據極少：** 僅級數、姓名等基礎欄位；進修／培訓／獲獎多為紙本。
- **排課：** 系統已有此功能，但今年遲到方式改動，設計未預料。

### 2.3 e-Class（打卡／家長通知／資產）

- **打卡機**＝Windows 機＋USB 讀卡器（原裝機昂貴，一部幾萬；壞後改用舊手提電腦＋USB 讀卡器）。
- **卡**由 e-Class 提供，十蚊一張（淘宝兩蚊），學校不滿。
- **家長 App（e-Class parent）：** 顯示子女返學／放學時間、學校通知。
- **數據存於香港**：涉跨境，廣大已於家長會讓家長簽署同意書。
- **資產管理**（總務部門用）：每年年尾盤點；教青局資助資產貼 serial number、拍照記錄；兩套編號（教青局＋校內）；系統約 **7 年**、功能陽春、只有盤點、無分析、無採購／報銷流程。

### 2.4 科大訊飛智學網

- 教青局以**先導計劃**方式推動，已行兩年，今年做**澳門本地化**（請各學科老師建澳門題庫）。
- 老師用於出卷、小測、測驗、考試；每年需學校提供教師**任教情況**回應系統。
- **目前未與成績表打通**；今年訊飛會進一步整合「成績表」部分；學校出卷後需將分數**導出 Excel → 核對 → 搬回自己系統**（各校系統不同）。

### 2.5 部署與伺服器

- 校方**無自建伺服器**（缺技術安全支援能力），歷來把系統外判託管。
- **師悅學籍系統**數據存於 **CTM 伺服器／VPS（澳門）**；CTM 負責電力／機櫃等基礎維護，應用層由校方 DBA／外判管理。
- **e-Class** 數據存於**香港**（家長已簽同意書）。
- 因**個資法「數據不出境」**，我方新系統傾向留在 CTM 本地；上雲需 hash／加密。馬sir 所屬公司本身亦於 CTM 設機櫃、自購 server，可作部署參考。
- 教青局今年推「智慧體育」，涉學生面容識別＋數據回澳，全澳暫無系統能合規處理，校方觀望中。

## 三、痛點

1. **系統碎片化、互不相通**：師悅學籍、e-Class、智學網、Excel 各說各話，數據靠人手搬運（導出 Excel→核對→匯入）。
2. **考勤／遲到口徑不一**：校門拍卡 vs 入課室點名是**兩套計算**；今年政策改為「**入課室才算遲到**」，系統設計未預料；班主任每朝要用手機逐個點名，繁瑣；且**無長期統計**（某學生一學期遲到／缺席幾多）。
3. **e-Class 又貴又封閉**：按功能收費偏貴、無 API、數據難導出、家長教育成本高、華為機裝唔到 APK（只有 App Store／Google Play）、卡常丟失需補卡；學校普遍不滿但被迫用（校門拍卡是硬性要求）。
4. **資產管理陽春**：只有盤點、無數據分析、無「採購→驗收→報銷→資產登記」全流程；校長無法一鍵掌握開支。
5. **行政審批全紙本、四度簽名**：老師申請 → 科組長／主任 → 副校長 → 校長，再付款、再報銷；過程無數據、易遺失、易扯皮；校長記唔住、查唔到開支明細（水電、科組、出外進修等）。
6. **教師評鑑（師評）完全空白**：現有系統都冇，校內評核現況「各施各法」；學校想做（帶班成績、專業性、進修、帶隊比賽、獲獎、教研／論文），但規則由朱sir 新建、**未定稿**（財政局預計三月才出）；教師進修／培訓／獲獎資料多為紙本、分散、重複填報。（勞校鄭校長曾做過評核機制，據聞舊設計有漏洞，可借鑑避坑。）
7. **數據出境合規壓力**：個資法要求學生／教師資料不出境；上雲受限；教師個資要 hash／加密；未成年學生跨境需監護人簽同意書（廣大已於家長會簽署，配合 e-Class 數據存港）。
8. **缺乏數據分析與可視化**：管理者靠印象、靠估，無實時、無趨勢圖表（呼應校長核心訴求：一按即出、關鍵字自由檢索、地址查詢、兄弟姊妹／校友關聯、升學追溯如「打北京大學」；火災時按地址即時篩出附近學生＝同 08-24 定稿所記勞校案例）。
9. **歷史檔案數位化困難**：1938 年至今紙本檔案珍貴，但保存／修復成本極高（一個月幾千蚊修復一本）。

## 四、後續方向建議

### A. 切入策略（最重要）

- **唔好一次過取代所有系統**：成熟系統（如 e-Class）難撼動，學校唔敢「成個換晒」（怕影響穩定）。
- **游擊隊打法**：集中火力做「最痛、最細、最快見效」的一個功能 → 老師覺得有用／得意 → 口碑 → 再擴張。
- **先搵「突破口」**：先問邊個係 user（老師／班主任）最痛嘅點；解決咗，佢就會接受其他功能。
- **定位為「補充」而非「取代」**：填現有系統（e-Class／科大訊飛／師悅）嘅空白；唔好正面撼大公司。

### B. 首期模塊：M2 教師（師評）＋ M5 行政審批（＋ M6 資產）

- **理由**：師評＋審批係所有現有系統嘅空白（唔撞車）；用戶係老師＋管理層；**校長肯推 → 可「強制」老師用 → 形成習慣 → 再推其他**（團隊：「老師一定會用」，但須配合學校政策）。
- **M2 師評**：先攞到老師各種 data（紙本＋電子檔），掃描／錄入歷史資料；配合朱sir 新建嘅評分規則（例：大課室一等獎 +1 分）；**規則未定稿前，先歸集現有教師數據**。朱sir 視角較宏觀，規則由其主導、團隊配合系統化。
- **M5 審批**：四級簽名電子化（老師→科組長／主任→副校長→校長）；加時間戳、留痕、避免扯皮；延伸到「採購→報銷→資產登記」一條龍（M6）。**切入點**：企業微信雖有內建審批，但馬sir 指其**難用、流程未必貼合校本需要**，且**澳門購買 WeCom 小程序／付費功能不便**（涉大陸付款）→ 自建審批正填此缺口。
- **M6 資產**：e-Class 資產數據如可導出則匯入取代，否則重新掃描；可考慮 **RFID／QFID** 盘点（錦上添花，一年盘点一次其實可接受）。
- **M1 學生暫緩**：學生數據已由師悅覆蓋，且朱sir／科大訊飛可能自建學生系統 → 為免撞車，學生模塊「之後再說」，先專注審批＋師評；日後重啟前先與朱sir／師悅對齊邊界。

### C. 數據整合／對接

- **主路徑＝CTM 伺服器**：師悅學籍數據存於學校 CTM 伺服器；調查該 server 上有哪些服務／數據，評估能否用**定時任務導出 → 定時導入我方系統**，避開各系統無 API 的限制（詳見 T4）。
- **e-Class 出勤**：校門拍卡只用於通知家長；**真正的遲到／考勤是老師在課室用 e-Class 點名**，故截取拍卡數據意義不大。e-Class 封閉無 API，其課室點名數據暫難取得。
- **智學網**：目前未與成績表打通；今年訊飛會進一步整合成績部分；**密切留意教青局方向**，避免重複對接、白花資源。
- **教師數據**：進修／培訓／獲獎多為紙本，需掃描＋錄入；貫徹「一次錄入、多方共享」。

### D. 部署與合規（對應 M9）

- **部署與產品形態**：**本地（雲）部署 webapp ＋ WeCom 小程序／PWA**；老師用 **WeCom 帳號登入（SSO）**，免記密碼、免裝新 app（M2 師評＋M5 審批＋資產皆可掛在此形態下）。
- **數據不出境**：學生／教師個資留在 CTM 本地；上雲需 **hash／加密**（例：教師編號可上，真名／身份證唔得；參考醫療數據「去識別化」做法）。
- **跨境同意**：未成年學生資料跨境需監護人簽同意書；廣大已於家長會讓家長簽署（配合 e-Class 數據存於香港）。
- **WeCom 限制**：免費版功能有限；付費版涉騰訊（大陸）付款流程，澳門學校付款麻煩；全澳學校掛喺教青局 WeCom 分帳下。

### E. 時間線

- 開學後（下星期）開始老師培訓（師悅學籍系統）。
- 師評規則：**財政局預計三月才出**；朱sir 正搭建新師評規則。
- 團隊目標：**出年 4 月前完成師評＋審批**。
- 先做 research：現況已清楚，改為**需求驅動**——先釐清師評＋審批流需要哪些數據，再針對性摸清（詳見五、T1–T3）。

### F. 商業與政策策略

- **目標市場**：全澳 **68 間私校**（76 所正式學校扣 8 所公校）；主攻**中小型學校**（人均成本高、無完整系統、資源少）；大校（2000–3000 人，如濠江、培正、勞校、聖保祿等）已有成熟系統、難撼動。
- **市場結構**：3000 人以上大校無幾所；1000–2000 人一類（如菜農，廣大約千幾人、中學 26 班）；純小學／幼稚園約三成（幾百到一千人）。
- **產品打法**：性價比高、易用、**減輕（唔係增加）勞動**；用家角度設計；界面靚、有圖表／趨勢線、操作簡單。
- **家長賣點（新想法）**：借鏡日本寄宿學校「卡」——每次消費通知家長，重點唔係錢，係家長知道子女食咩、消費模式（健康）。此模式日後或可擴大到大校。
- **背書／政策**：善用澳門扶持青年創業、產業多元化政策；爭取教青局資助（AI 專項，傳一間學校一兩百萬）；透過中聯辦、北大、特區政府、經濟／科技部門推介；定位「愛國愛澳、服務環球回饋澳門」。
- **示範**：以廣大作示範案例，做出口碑帶動其他學校。
- **與大公司關係**：唔好正面撼科大訊飛；可做配套／補充，甚至被收購／合作（訊飛需澳門本地實體，中間有 partner 轉手）。
- **自身優勢／劣勢**：優勢＝新技術、成本低（無大團隊包袱）、靈活；劣勢＝人手少、時間有限 → 更要集中火力。
